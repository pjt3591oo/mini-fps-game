# FPS Arena 기획 노트

사이클마다 **진단 → 후보 → 타당성 검토 → 개발 → 플레이테스트 결과** 순서로 기록한다.
타당성은 세 가지로 본다: **가치**(플레이 경험에 주는 효과), **비용**(구현·검증 시간), **위험**(기존 시스템·협동 동기화·밸런스를 깨뜨릴 가능성).

## 게임의 뼈대 (현재)

- 장르: 웨이브 서바이벌 FPS, 솔로 + 협동
- 한 판의 흐름: 웨이브 전투 → 클리어 보상(체력, 특성 1개 선택) → 다음 웨이브, 5웨이브마다 보스
- 플레이어 수단: 무기 4종, 정조준, 수류탄, 드럼통 유폭, 지형(언덕·망루·엄폐물)
- 적: 병사, 돌격병, 사수, 자폭병, 중장갑, 보스

## 사이클 1 — "피하는 재미"와 "처음 5분"

### 진단

| 영역 | 문제 | 근거 |
| --- | --- | --- |
| 전투 깊이 | 방어 수단이 '뒤로 걷기'뿐이다. 보스 돌진·투사체를 보고도 피할 방법이 달리기밖에 없다 | 봇 테스트에서 회피 없는 봇은 전부 보스 웨이브에서 사망 |
| 접근성 | 난이도가 하나뿐이라 초보와 숙련자를 동시에 만족시킬 수 없다 | 조준 실력 0.3~0.7 봇이 모두 같은 지점(10웨이브)에서 끝남 |
| 온보딩 | 조작 안내가 메뉴의 글 세 줄이 전부. 사수의 발사 예고, 자폭병 대처법 등은 죽어 봐야 안다 | 첫 판 이탈 위험 |
| 타격감 | 적이 죽으면 파티클만 남기고 즉시 사라져 처치의 무게가 없다 | 스크린샷 검토 |
| 설정 | 음량·시야각 조절이 없다 | FPS의 기본 편의 기능 |

### 후보와 타당성

| 후보 | 가치 | 비용 | 위험 | 판정 |
| --- | --- | --- | --- | --- |
| 대시(짧은 무적 회피, 재사용 대기) | 높음 — 회피가 실력 요소가 됨 | 낮음 | 중간 — 너무 강하면 근접 적이 무의미 → 대기시간 2.5초, 무적 0.2초로 제한 | **채택** |
| 난이도 3단계 | 높음 | 낮음 | 낮음 — 협동에서는 호스트 설정을 따르게 함 | **채택** |
| 상황별 힌트(처음 만난 적, 탄약 부족 등, 1회만) | 중간 | 낮음 | 낮음 | **채택** |
| 적 사망 연출(쓰러짐) | 중간 | 낮음 | 낮음 — 시체는 판정에서 제외 | **채택** |
| 음량·시야각 설정 | 중간 | 낮음 | 낮음 | **채택** |
| 슬라이딩·벽 타기 등 이동기 확장 | 중간 | 높음 | 높음 — 충돌 처리 전면 수정 필요 | 보류 |
| 배경 음악 | 중간 | 중간 | 중간 — 합성음만으로는 품질 확보가 어려움 | 보류 |

### 결과

- 대시(`Q`), 난이도 3단계, 상황별 힌트 8종, 적 쓰러짐 연출, 음량·시야각 설정을 넣었다.
- 봇 테스트(보통 난이도, 10분 제한): 대시를 쓰는 봇 한 판은 12웨이브 이상 생존, 나머지 두 판은 첫 보스(5웨이브)에서 사망. **결과가 보스전에서 크게 갈린다** → 보스 공격이 읽히지 않는다는 신호. 사이클 2에서 다룬다.
- 화면 확인: 힌트 표시, 대시 대기시간 막대, 메뉴의 난이도·설정 정상.

## 사이클 2 — "판마다 다른 전개"와 "다시 하고 싶은 이유"

### 진단

| 영역 | 문제 | 근거 |
| --- | --- | --- |
| 반복성 | 웨이브가 숫자만 커진다. 3판쯤 하면 전개를 다 본다 | 웨이브 구성이 '수 × 체력' 스케일링뿐 |
| 빌드 | 특성이 전부 수치 +N%라 판마다 플레이 방식이 달라지지 않는다. 마음에 안 드는 3장이 나와도 대안이 없다 | 특성 8종 모두 단순 증가형 |
| 보스전 공정성 | 돌진 방향을 알 수 없어 맞고 나서야 안다 | 사이클 1 봇 테스트의 보스전 편차 |
| 재도전 동기 | 게임 오버 화면에 점수뿐. 무엇을 잘했고 못했는지, 기록을 깼는지 알 수 없다 | 최고 점수만 저장 |

### 후보와 타당성

| 후보 | 가치 | 비용 | 위험 | 판정 |
| --- | --- | --- | --- | --- |
| 웨이브 변이(광란·안개·물량 공세 등 7종, 3웨이브부터 확률 등장) | 높음 | 낮음 — 기존 수치에 배율만 곱함 | 중간 — 난이도 급변 → 보스 웨이브 제외, 배율 상한 | **채택** |
| 희귀 특성(플레이 방식이 바뀌는 5종) + 다시 뽑기 1회 | 높음 | 중간 | 중간 — 연쇄 폭발이 과하게 강할 수 있음 → 자기 피해 없음, 피해량 낮게 | **채택** |
| 보스 돌진 경로 표시(바닥의 붉은 띠) | 높음 | 낮음 | 낮음 | **채택** |
| 결과 화면(명중률·헤드샷·생존 시간) + 누적 기록 | 중간 | 낮음 | 낮음 | **채택** |
| 재화 + 상점(무기 구매·강화) | 높음 | 높음 — 마우스 UI, 가격 밸런스, 협동 동기화 | 높음 | 보류 — 특성 시스템과 역할이 겹침. 희귀 특성 반응을 본 뒤 재검토 |
| 두 번째 맵 | 높음 | 높음 | 낮음 | 보류 — 변이로 먼저 변주를 확보 |

### 결과

- 웨이브 변이 7종, 희귀 특성 5종(금색 카드) + `R` 다시 뽑기, 보스 돌진 경로 표시, 결과 화면과 누적 기록을 넣었다.
- 테스트 중 발견해 고친 것: **보스 체력 막대가 처음부터 표시되지 않던 버그**(CSS 선택자 충돌), 체력이 최대치를 넘으면 막대가 화면 밖으로 늘어나던 문제.
- 봇 테스트: 세 판 중 두 판이 10웨이브(두 번째 보스), 한 판이 5웨이브에서 종료. 돌진을 옆 대시로 피하는 것은 시나리오 테스트로 확인.
- 협동 테스트: 변이·난이도 정보가 스냅샷에 실려 동기화되고, 호스트 이전도 정상.

## 사이클 3 — "웨이브 안에서의 변화"와 "움직일 이유"

### 진단

| 영역 | 문제 | 근거 |
| --- | --- | --- |
| 위치 선정 | 중앙 언덕에서 버티는 것이 항상 정답이다. 맵의 나머지 80%를 쓸 이유가 없다 | 봇이 언덕 근처에서만 싸워도 10웨이브 도달 |
| 웨이브 내 완급 | 한 웨이브 안에서는 '적이 줄어든다' 외에 사건이 없다 | 웨이브 중 이벤트 0개 |
| 마무리 지연 | 마지막 한두 마리를 찾느라 10~20초가 빈다 | 초기 플레이테스트 로그(남은 적 1 상태로 15초 이상) |
| 타격 정보 | 중장갑처럼 체력이 높은 적은 얼마나 남았는지 알 수 없고, 강한 한 방에도 적이 반응하지 않는다 | 피해 숫자만 표시 |

### 후보와 타당성

| 후보 | 가치 | 비용 | 위험 | 판정 |
| --- | --- | --- | --- | --- |
| 보급품 투하(웨이브 중 맵 외곽에 낙하, 빛기둥·미니맵 표시) — 로켓 발사기 / 피해 증폭 / 보호막 | 높음 — 언덕을 떠날 이유, 웨이브 중 사건 | 중간 — 픽업 동기화 재사용 | 중간 — 로켓 자폭, 밸런스 → 탄 4발 제한 | **채택** |
| 남은 적 3마리 이하일 때 위치 표시(화면 가장자리 화살표) | 높음 | 낮음 | 낮음 | **채택** |
| 적 머리 위 체력 막대(피해를 입은 적만) | 중간 | 낮음 | 낮음 | **채택** |
| 강한 한 방에 경직(최대 체력의 25% 이상 피해, 보스 제외) | 중간 — 샷건·저격총의 역할 강화 | 낮음 | 중간 — 무한 경직 → 경직 중 재경직 불가 | **채택** |
| 거점 방어·호위 등 목표형 웨이브 | 높음 | 높음 | 중간 | 보류 — 보급품으로 이동 동기를 먼저 검증 |
| 협동 부활(쓰러진 동료 옆에서 3초) | 높음(협동 한정) | 중간 | 중간 | 다음 사이클 후보 |

### 결과

- 보급품 투하(로켓 발사기·피해 증폭·보호막), 남은 적 위치 표시, 적 체력 막대, 경직을 넣었다.
- 시나리오 테스트: 저격총 한 발에 중장갑 경직 확인, 로켓 한 발로 뭉친 병사 5마리 처치, 보급품 낙하→획득→효과 적용, 남은 적 2마리에 표시 2개.
- 회귀 테스트: 협동 동기화와 호스트 이전 정상. 봇 도달 웨이브는 5 / 10 / 13+로 이전과 비슷한 분포(봇은 보급품을 주우러 가지 않으므로 보급품의 실제 효과는 사람 플레이로 확인 필요).
- 미검증: "보급품이 실제로 언덕을 떠나게 만드는가"는 사람 플레이 데이터가 있어야 판단할 수 있다.

## 사이클 4 — "같이 하는 재미"와 "보는 맛"

### 진단

| 영역 | 문제 | 근거 |
| --- | --- | --- |
| 협동 상호작용 | 같이 쏘는 것 말고는 서로에게 할 수 있는 일이 없다. 쓰러지면 웨이브가 끝날 때까지 구경만 한다 | 협동 전용 행동 0개 |
| 협동 소통 | 음성 없이 "저기!"를 전할 방법이 없다 | 표시 기능 없음 |
| 외형 | 적이 전부 캡슐 + 공이다. 움직임이 미끄러지는 것처럼 보인다 | 스크린샷 검토 |
| 분위기 | 하늘이 단색이라 공간감이 없다 | 스크린샷 검토 |
| 경쟁 동기 | 기록이 내 브라우저에만 남는다. 친구와 비교할 수 없다 | localStorage만 사용 |

### 후보와 타당성

| 후보 | 가치 | 비용 | 위험 | 판정 |
| --- | --- | --- | --- | --- |
| 협동 부활(쓰러진 동료 옆에서 `F` 2.5초) | 높음 | 중간 | 중간 — 부활 직후 즉사 → 부활 후 1.5초 무적 | **채택** |
| 위치 표시(`V`, 5초간 빛기둥 + 미니맵) | 중간 | 낮음 | 낮음 | **채택** |
| 적 팔다리 + 걷기 애니메이션 | 높음 — 첫인상 | 낮음 | 낮음 — 판정 부위만 추가 | **채택** |
| 그라데이션 하늘 | 중간 | 낮음 | 낮음 | **채택** |
| 서버 순위표(상위 10개, 메뉴에 표시) | 중간 | 낮음 | 낮음 — 조작 가능하지만 지인끼리 쓰는 서버라 허용 | **채택** |
| 대전(PvP) 모드 | 높음 | 높음 — 피격 판정·리스폰·밸런스 전부 신규 | 높음 | 보류 |
| 음성/텍스트 채팅 | 낮음 | 중간 | 낮음 | 기각 — 위치 표시로 대체 |

### 결과

- 협동 부활(`F` 2.5초, 부활 후 1.5초 무적), 위치 표시(`V` / 휠 클릭), 적 팔다리와 걷기 애니메이션, 그라데이션 하늘, 서버 순위표(`data/scores.json`)를 넣었다.
- 2인 테스트: 쓰러짐 → 동료 화면에 누운 모습과 안내 표시 → F 유지로 부활(체력 50) → 위치 표시가 상대 화면·미니맵에 나타남을 확인.
- 회귀 테스트: 판정 부위가 3개에서 7개 이상으로 늘었지만 봇 도달 웨이브 분포는 그대로(5 / 10 / 10+).

## 사이클 5 — "두 번째 무대"와 "두 번째 보스"

### 진단

| 영역 | 문제 | 근거 |
| --- | --- | --- |
| 무대 | 맵이 하나라 지형 학습이 끝나면 새로움이 없다. 탁 트인 광장이라 저격총이 지나치게 유리하다 | 맵 1종 |
| 장기 플레이 | 10웨이브 이후에도 같은 보스가 체력만 늘어 다시 나온다 | 봇이 10웨이브 이상 도달하는 판이 꾸준히 나옴 |
| 보스 대응 | 첫 보스는 '옆으로 피하기'만 요구한다. 자리를 계속 옮기게 만드는 압박이 없다 | 보스 패턴 1종 |

### 후보와 타당성

| 후보 | 가치 | 비용 | 위험 | 판정 |
| --- | --- | --- | --- | --- |
| 맵 '창고 지구'(건물로 시야가 끊기는 근·중거리 맵) + 메뉴에서 선택, 협동은 호스트 맵을 따름 | 높음 | 중간 — 맵 형식·길찾기는 이미 범용 | 낮음 | **채택** |
| 보스 '포격대장'(10웨이브마다, 예고 원 → 폭발) | 높음 | 중간 | 중간 — 예고가 안 보이면 불합리 → 원이 차오르는 연출 + 첫 등장 힌트 | **채택** |
| 맵 투표 | 낮음 | 중간 | 낮음 | 기각 — 호스트 선택으로 충분 |
| 절차적 맵 생성 | 중간 | 높음 | 높음 — 막힌 지형 검증 필요 | 보류 |

### 결과

- 맵 '창고 지구'와 보스 '포격대장'을 넣었다. 보스 판정은 종류 이름 대신 `boss` 플래그로 일반화해 이후 보스 추가가 쉬워졌다.
- 새 맵 봇 테스트: 200초에 6웨이브 도달, 적이 건물을 돌아 플레이어에게 도달함(길찾기 정상), 첫 보스 격파.
- 포격: 제자리에 서 있으면 첫 탄에 35, 연속으로 맞으면 57 피해. 예고 원과 보스 이름 표시 확인.
- 협동: 호스트가 고른 맵으로 참가자의 맵이 자동 전환됨을 확인.
- 봇은 포격을 피하지 못해 두 판 모두 10웨이브에서 종료 → **사람이 피할 수 있는 난이도인지는 직접 플레이로 확인 필요.**

## 사이클 6 — 디자인 ("한 장면으로 기억되는 화면")

## 사이클 8 — 아이템 · 강화 · 상점 (사용자 지시)

사이클 2에서 "특성과 역할이 겹친다"는 이유로 보류했던 재화·상점을 사용자 지시로 도입했다. 겹침을 피하려고 역할을 나눴다: **특성**은 웨이브마다 무료로 고르는 플레이어 성장, **상점**은 크레딧을 어디에 쓸지 정하는 무기 성장과 소모품.

### 설계

| 시스템 | 규칙 |
| --- | --- |
| 크레딧 | 처치 시 적 점수의 10%(헤드샷 1.5배), 웨이브 클리어 20 + 5×웨이브, 보급품 획득 40. 협동에서는 각자 따로 모은다 |
| 상점 | 웨이브 사이에 `B`. 마우스로 구매. 솔로는 상점을 보는 동안 다음 웨이브가 멈추고, 협동은 웨이브 사이 시간을 20초로 늘렸다 |
| 강화 | 무기 4종 각각 +7까지. 단계마다 피해 +10%, +3 탄창 25% 증가, +5 재장전 20% 단축, +7 연사 15% 증가. 비용 60~420, 성공 확률 100%~40%. 실패해도 단계는 유지되고 다음 확률이 10%p 오른다 |
| 아이템 | 구급 주사(`Z`, 체력 60), 방어막(`X`, 6초간 피해 70% 감소), 폭격 요청(`T`, 조준 지점에 2초 뒤 폭발). 종류별 2~3개까지 보유 |
| 보급 | 탄약 50% 보충, 수류탄 2개, 체력 완전 회복 (즉시 적용) |

### 타당성

| 항목 | 판단 |
| --- | --- |
| 가치 | 높음 — 처치에 점수 외의 보상이 생기고, 판마다 "어느 무기를 키울지"가 갈린다. 사이클 7에서 미룬 '무기 숙련'의 목적(무기 선택 이유)을 대신한다 |
| 비용 | 중간 — 상점 화면, 마우스 잠금 전환, 무기 수치 계산 경로 수정 |
| 위험 | 강화로 피해가 최대 +70% 올라 후반 난도가 무너질 수 있음 → 비용을 가파르게, 확률을 낮게 잡았고 밸런스 기획자의 검토 대상으로 넘긴다. 상점이 웨이브 사이 흐름을 끊을 수 있음 → 열지 않으면 기존과 같은 속도로 진행 |

### 결과

- 시나리오 테스트: 1웨이브에서 크레딧 115 획득. 상점을 연 동안 타이머 정지. 버튼 클릭으로 강화·아이템·보급 구매. 샷건 +6의 한 발 피해 144 → 207. 구급 주사·방어막(50 피해가 15로)·폭격(중장갑에 384 피해) 동작.
- 봇 테스트(봇이 소총 강화와 구급 주사를 사서 씀): 도달 웨이브 5 / 10 / 10으로 이전과 같은 분포. 강화가 봇의 보스전 결과를 바꾸지는 못했다.
- 미검증: 실제 브라우저에서 상점을 열고 닫을 때의 마우스 잠금 전환(테스트 모드는 잠금을 쓰지 않음), 협동에서의 상점 이용, 가격과 확률의 적정성.

### 결과

- 채택안을 모두 반영했다.
- 시나리오 테스트: 보스 옆에 서 있으면 원이 차오른 뒤 35 피해("보스 내려찍기"), 물러나면 0. 척탄병이 중앙 고지의 플레이어에게서 가려진 포대 지점 `[29.5, 12]`로 이동해 머물며 30초 동안 서 있는 플레이어를 3번 맞힘("척탄병 포격"). 특성을 고른 뒤에도 웨이브가 바로 시작되지 않고 안내 줄에 남은 시간 표시. 상점을 여는 동안 타이머 정지와 특성 카드 숨김, 닫은 뒤 3초 보장. 확정 강화(50% 단계에서 640)로 +5 달성. 아이템이 없을 때 안내 문구. T를 누르는 동안 폭격 범위 표시, 떼면 요청.
- 봇 테스트: 도달 웨이브 10 / 10 / 5. 5웨이브 사망 원인이 "보스 근접"에서 "보스 내려찍기"로 바뀌었다. 봇은 원을 보고 물러나지 않으므로 이 수치로 보스 난도를 판단할 수 없다. 웨이브 사이 대기가 길어져 10웨이브 도달 시간이 약 430초에서 530초로 늘었다.
- 미검증: 척탄병이 사람을 실제로 고지에서 움직이게 하는지.

### 추가 검증 (협동, 마우스 잠금)

미검증으로 남겼던 항목을 자동 테스트로 확인했다. 스크립트는 `tools/test-coop-systems.js`, `tools/test-pointer-lock.js`, `tools/test-pointer-lock-fail.js`.

- **찾아서 고친 버그 2건** (둘 다 협동 참가자에게만 나타남)
  - 웨이브 클리어 신호가 참가자에게 전달되지 않았다. 사이클 8에서 메시지에 넣은 `t`(남은 시간) 필드가 메시지 종류 필드 `t`를 덮어썼기 때문이다. 참가자는 특성 선택, 클리어 크레딧, 체력 회복을 받지 못하고 있었다.
  - 같은 원인으로 포격 예고 원이 참가자 화면에 한 번도 표시되지 않았다(사이클 5부터). 참가자는 경고 없이 폭발만 맞았다.
  - 재발 방지: `net.send`가 메시지 종류를 항상 마지막에 써서 덮어쓸 수 없게 했다.
- 협동 확인 결과: 지원 수당(호스트가 병사 처치 → 호스트 10, 참가자 3 / 참가자가 중장갑 처치 → 참가자 30, 호스트 8), 내려찍기 원이 참가자 화면에 표시됨, 포격대장 포격과 폭격 요청의 예고 원이 참가자 화면에 표시됨, 참가자의 상점 열기·남은 시간 표시·강화 구매, 협동에서는 상점 중에도 타이머가 흐름, 웨이브 시작 시 두 사람의 상점이 닫히고 특성이 무작위 지급됨.
- 마우스 잠금(실제 잠금 사용): 상점을 B·Esc·닫기 버튼으로 닫을 때, B를 빠르게 네 번 누를 때, 입력 없이 강제로 닫힐 때(2.5초·7초 뒤) 모두 잠금이 복귀했다. 일시정지에서 Enter로 복귀, 메인 메뉴 두 번 누르기도 동작.
- 잠금 실패(강제로 만든 상황): 잠금이 거부되면 "마우스를 다시 잡지 못했습니다" 안내와 함께 일시정지로 넘어가고 계속하기로 복구된다. 잠금 요청이 아무 반응 없이 무시되는 경우는 복구 경로가 없어서 0.6초 뒤 확인하는 감시를 추가했다.
- 여전히 확인할 수 없는 것: 사용자가 직접 Esc를 누른 직후 브라우저가 잠금을 잠시 거부하는 동작은 자동화로 재현되지 않는다(위의 거부 처리 경로로 들어오도록 만들어 두었다).

## 사이클 10 — 상점 확장 (사용자 지시 + 사이클 9 보류안)

사용자의 "상점 시스템 추가" 지시를 상점 확장으로 받아, 사이클 9에서 다음으로 미뤘던 시스템 기획자의 상점 재편안(`docs/planning/cycle-9/system-designer.md` 안 1)을 구현했다.

### 진단

| 문제 | 근거 |
| --- | --- |
| 강화 효과가 무료 특성과 같은 식에 곱해지고(피해·재장전·연사) 네 무기 모두 같아, 소총만 키우는 것이 항상 이득이다 | 시스템 기획자의 코드 확인, 밸런스 기획자의 +7 지속 화력 표(소총 430 / 샷건 260 / 저격총 171) |
| 응급 처치는 기다리면 공짜, 수류탄 2개는 탄약 픽업마다 +1과 겹친다 | 자연 회복 17초, `addAmmo` |
| 상점과 특성이 서로 맞물리지 않는다 | 크레딧으로 특성 운에 개입할 방법이 없음 |

### 채택 내용

| 항목 | 내용 |
| --- | --- |
| 무기별 고유 효과 | +5 / +7을 무기마다 다르게: 소총(정조준 퍼짐 40% 감소 / 헤드샷 처치 3발 환급), 샷건(산탄 11발 / 사거리 +50%), 저격총(관통 4 / 헤드샷 처치 1발 환급), 권총(헤드샷 배율 3.5 / 처치마다 대시 대기 0.5초 감소). 기존의 공통 재장전·연사 효과는 제거 |
| 특성 개입권 | 다시 뽑기권(40, 2장까지), 희귀 보장권(150, 1장) — 다음 특성 선택에 적용 |
| 로켓 발사기 구매 | 160 크레딧에 4발. 보급품으로만 얻던 무기를 살 수 있게 함 (총괄 추가) |
| 품목 정리 | 응급 처치·수류탄 2개 삭제 |
| 판 기록 | 품목별 구매 수(`bought`) 추가 |

### 결과

- 시나리오 테스트: 다시 뽑기권 2장·희귀 보장권 1장까지만 구매됨, 다음 특성 선택에서 첫 카드가 희귀이고 다시 뽑기 3회 가능, 로켓 구매 후 재구매 차단, 샷건 +5에서 한 발에 11개 명중, 권총 +7 처치 시 대시 대기 2.42 → 1.90초, 소총 +7 헤드샷 처치 시 탄창 10 → 13.
- 미검증: 무기별 효과가 실제로 "소총 한 길"을 깨는지(사람 판 기록의 `lv`·`bought`로 판단), 희귀 보장권 가격의 적정성. 밸런스 기획자의 검토 대상.
