# 사이클 12 시스템 기획자 안 — 보관함(인벤토리)과 선택지: 초안 검토와 보완

검토 대상: `docs/planning/cycle-12/director-proposal.md`(총괄 초안).
근거로 읽은 코드: `public/js/meta.js`, `config.js`의 `META`, `main.js`(훈장 알림 183~206행, `applySkin` 209행, `kitPicker`·`showProgress` 427~482행, `toMenu` 496행, 보급품 훅 106행, 처치 훅 87행), `perks.js`, `weapons.js`(`setGunSkin` 181행, `fire` 264행), `enemies.js`(`onEnemyKilled` 543행, 보급 투하 821·841행, 픽업 626행), `net.js`(`connect` 26행), `server.js`(`join` 104행, `addScore` 28행), `player.js` 145행, `hud.js` 162행.

전제: 사용자가 정한 "수치 없는 수집형 보관함"은 그대로 둔다. 아래는 그 틀이 사이클 11 코드와 어디서 부딪히는지, 무엇을 고치면 바로 만들 수 있는지에 대한 검토다.

### 1-2. 협동에서 확인한 것

- **드롭은 로컬에서 처리해도 된다.** 웨이브 클리어(`net.send('wave')` 뒤 `onWaveClear`)는 모든 클라이언트의 `G.hooks.waveClear` → `metaWaveClear`로 들어온다. `metaWaveClear`의 `info.n <= run.cleared` 검사가 호스트가 바뀔 때의 중복을 막는다. 보스 드롭을 이 검사 **뒤**에서 굴리면 중복 방지도 함께 얻는다.
- **보급품은 한 사람만 줍는다.** 보급품을 주우면 `pkt` 메시지로 상자가 모두에게서 사라지고, `supplyPick` 훅은 주운 사람에게서만 돈다. 보급품은 2웨이브부터 웨이브마다 하나씩 떨어지므로(`supplyT`) 10웨이브 판이면 약 9개다. "주운 사람만 10%"로 하면 협동에서 **드롭을 위해 보급품을 서로 먼저 주우려는 경쟁**이 생긴다. 보급품 효과(로켓·증폭)는 지금도 한 사람 몫이라 이 경쟁은 동료가 쓸 수 있었던 효과를 빼앗는다.
- **칭호는 접속 메시지에 실어야 한다.** `server.js`의 `join` 처리는 `name`만 받아 `room.clients`에 저장하고, `welcome.players`와 `playerJoined`에 `{ id, name }`만 넣는다. 클라이언트(`net.js` 46·49행)는 `new RemotePlayer(p.id, p.name)`만 만든다. 동료 목록은 `hud.js` 162행, 머리 위 이름표는 `net.js`의 `nameSprite`다.
- **판 도중에는 칭호가 바뀌지 않는다.** `toMenu`가 `net.disconnect()`를 부르므로 보관함(메뉴)을 여는 순간 이미 방을 나간 상태다. 그래서 칭호 변경 메시지는 필요 없고 `join`에 한 번 싣는 것으로 충분하다. `ps`(초당 15회)에 넣으면 낭비다.
- **순위표 칭호는 비용이 다르다.** `addScore`는 필드를 하나씩 검사해서 저장한다(이름 16자, 점수, 웨이브, 난이도, 협동). 칭호를 넣으려면 서버의 순위표 스키마와 저장 파일이 바뀌고, 이미 쌓인 기록에는 칭호가 없다.
- **처치 무기 판정의 오차**: `G.hooks.kill`은 처치 순간의 `W.current`로 무기를 센다. 협동 클라이언트는 호스트의 `kill` 메시지가 돌아온 순간(약 0.1초 뒤)이고, 수류탄·드럼통·연쇄 폭발 처치도 들고 있던 무기로 센다. 숙련도(사이클 11)도 이미 같은 방식이다. 특화 특성의 "이번 판 10처치" 조건도 이 오차를 그대로 안는다. 10처치 문턱에서 1~2처치 차이라 받아들일 만하다고 본다.

### 1-3. 특성 쪽에서 확인한 것

- `perks.js`의 `draw`는 일반 특성을 **장수 제한 없이** 섞어서 뽑는다. 초안의 "2장까지"를 지키려면 특성마다 `max` 필드를 두고, `draw`에서 `G.perks[name] >= max`인 것을 뺀다. 기존 일반 8종은 `max`가 없으니 그대로 둔다.
- 카드 아이콘은 `icons.js`의 특성 이름 표(45행~)로 찾는다. 새 특성 8종에 아이콘 8개가 필요하다. 없으면 빈 칸이 된다.
- **숨 고르기**: `player.js` 145행이 `PLAYER.REGEN_DELAY`를 바로 쓴다. `BASE_MODS`에 `regenDelay: 1`을 넣고 `PLAYER.REGEN_DELAY * G.mods.regenDelay`로 바꾸면 된다. 2장이면 5 → 3.5 → 2.45초다. 초안의 "최소 2초"는 2장 제한 안에서는 작동하지 않으니 지워도 된다.
- **근접 사격**: `weapons.js` `fire`의 `h.distance`는 카메라에서 맞은 점까지의 거리라 그대로 쓸 수 있다(317행 거리 감쇠도 같은 값을 쓴다). 넣을 곳은 316~317행이다. 이렇게 하면 수류탄·로켓·연쇄 폭발에는 적용되지 않는다(이 피해들은 `fire`를 거치지 않음). 그러나 초안의 "소총 위주 플레이에는 효과가 작다"는 근거가 약하다. 돌격병·자폭병·병사 근접은 모두 10m 안에서 일어나므로 소총 사용자도 상당한 효과를 본다. 수치 판단은 밸런스 기획자에게 넘긴다.
- **보급 전문가**: `main.js` 106행 `supplyPick`의 분기(`r < 0.4` 로켓, `< 0.75` 증폭, 나머지 체력)를 "세 효과 중 겹치지 않게 2개"로 바꾸면 된다. 해금 판정에는 C8의 누적 칸이 필요하다.
- **전리품**: 87행 처치 훅의 `addCredits`에만 ×1.3을 곱한다. 지원 처치(`assist`)·웨이브 보상·보급 크레딧에는 곱하지 않는다. 크레딧은 각자 로컬이라 협동 문제는 없다.
- **해금 판정의 시점**: 판 도중 '첫 보스' 훈장을 따면 같은 판의 다음 카드부터 숨 고르기가 나오는가? 초안에 없다. 판 중간에 풀이 바뀌면 "왜 갑자기 이 카드가"가 생기고, 협동에서 테스트 재현도 어렵다.

### 1-4. 무기 특화 특성 규칙 "이번 판 그 무기로 10처치 이상일 때만 카드에 나옴"의 타당성

- **방향은 맞다.** 쓰지 않는 무기의 특성이 카드에 나오면 그 카드는 죽은 카드다. 조건을 이번 판 사용 실적으로 거는 것은 희석을 줄인다.
- **그러나 희석은 남는다.** 소총 숙련 2단계(250처치)인 사람은 거의 모든 판에서 2웨이브 안에 소총 10처치를 넘긴다. 그러면 일반 풀이 8 → 10(해금 2종) → 11(점사 제어)이 된다. 초안의 모의 실험대로면 원하는 일반 특성 하나를 볼 확률이 29.8%에서 약 22%로 떨어진다.
- **특화 특성이 쌓이는지 정해져 있지 않다.** 일반 특성이고 `max`가 없으면 점사 제어를 세 번 받아 퍼짐 누적 상승이 0.7³ = 34%로 떨어진다. 한 번만 얻게 해야 한다.
- **권총 '속사 권총'(연사 간격 −20%)은 사람에게 거의 보이지 않는다.** 권총은 단발(`auto: false`)이고 연사 간격은 0.16초(초당 6.25발)다. 사람이 클릭할 수 있는 속도가 대개 초당 6~8회라, 0.128초로 줄여도 대부분 손이 먼저 한계에 닿는다. 봇은 혜택을 다 받으므로 봇 비교와 사람 체감이 어긋나는 특성이다.
- **로켓이 빠진 이유가 적혀 있지 않다.** 로켓은 보급품으로만 얻는 무기(`dropOnly`)라 특화 특성을 둘 수 없다. 숙련도 표(`META.mastery.rocket`)는 있으니 "로켓은 숙련 2단계 보상 없음"을 화면에 적어야 한다.

### 1-5. 초안에서 과한 것

- **순위표 칭호**: 서버 순위표 스키마를 바꿔야 하고 얻는 것은 작다(순위표는 상위 5개만 보이고 기존 기록에는 칭호가 없음). 동료 목록·이름표 칭호만으로 "남에게 보이는 보상"은 충분하다.
- **전설 무기 색의 "발광 무늬"**: 무늬는 텍스처나 셰이더가 필요하다. 지금의 `setGunSkin`은 재질 색만 바꾼다. 은은한 자체 발광색(`emissive`)이면 재질 값 하나로 끝난다.
- **수집 격자 "18 + 5칸, n / 23"**: 칭호(계급 10 + 훈장 5)는 빠지고 계급 색 5종만 들어간다. 분모가 무엇을 세는지 사람이 알기 어렵다. 드롭 18종만 "수집"으로 세고, 계급·훈장으로 여는 것은 "해금"으로 따로 보여 준다(조건으로 계산하는 것이라 이미 다른 성격이다).

| 켜고 끄기 `perksOff` | **채택** | 특화 특성 4종도 같은 목록에서 끈다 |
| 수집 격자 분모 | **수정** | 드롭 18종만 "수집 n / 18". 계급 색·칭호는 "해금" 칸으로 분리 |
| D. 판 기록 요약 도구 | **채택** | 메타 항목에 `drops`(이번 판 드롭)와 해금 특성 선택 수를 더 센다 |

## 3. 구체 설계

### 3-1. 물건 카탈로그 (`config.js`의 `META.items`)

모든 보관함 물건을 한 표에 둔다. `src`가 소유 판정 방법을 정한다.

```js
// src: 'drop'(owned에 기록) | 'rank'(계급) | 'mastery'(그 무기 숙련 3단계) | 'ach'(훈장) | 'rankTitle'(계급명)
// kind: 'skin' | 'title' | 'killfx'
// grade: 'common' | 'rare' | 'legend' (드롭만)
items: {
  // 계급·숙련 색 (사이클 11의 META.skins를 옮김. 키는 그대로 둬서 이관을 단순하게)
  desert:  { kind: 'skin', src: 'rank', rank: 6, name: '사막',   color: 0xb59a6a },
  ...
  mastery: { kind: 'skin', src: 'mastery', name: '숙련 금장', color: 0xc8a040 },
  // 드롭 (3-2의 표)
  'd-teal': { kind: 'skin', src: 'drop', grade: 'common', name: '청록', color: 0x2f8f8a },
  ...
  // 훈장 칭호
  't-warlord': { kind: 'title', src: 'ach', ach: 'warlord', name: '포격 사냥꾼' },
  ...
}
```

- 소유 판정은 `meta.js`의 `has(id, weapon?)` 하나로 한다. `drop`은 `meta.inv.owned[id]`, `rank`는 `rankOf().rank >= rank`, `mastery`는 `masteryTier(weapon).tier >= 3`, `ach`는 `meta.ach[ach]`, 계급명은 `r-1`~`r-10` 같은 id로 `rank >= n`.
- `META.skins`는 지우지 않고 `META.items`에서 만들어 내도(같은 객체를 참조) 된다. `skinOpen`·`unlocksAt`은 `has`를 부르도록 바꾼다.

### 3-3. 드롭 규칙 (구현 위치 포함)

`meta.js`에 `rollDrop(source, grade = null, rng = Math.random)`을 둔다. `rng`는 테스트에서 고정값을 넣기 위함이다.

| 사건 | 확률 | 굴리는 곳 | 조건 |
| --- | --- | --- | --- |
| 보스 웨이브(5의 배수) 클리어 | 40% | `metaWaveClear`, `info.n <= run.cleared` 검사 뒤, `info.n % 5 === 0`일 때 | `run.waveSeen === info.n` — `metaWaveStart`에서 `run.waveSeen = info.n`을 남긴다. 웨이브 시작을 못 본 중간 참가자는 굴리지 않는다. 쓰러져 있어도 굴린다(웨이브 XP와 같은 규칙) |
| 보급품 수령 | 10% | 혼자: `supplyPick` 훅. 협동: 내가 주우면 `supplyPick`, 동료가 주우면 `pkt` 수신 처리에서 그 픽업이 `supply`일 때 | 협동에서 방 전원이 각자 한 번씩. 수신 처리는 기존 `pkt` 핸들러에서 픽업을 지우기 전에 `type`을 확인한다. 새 메시지는 필요 없다 |
| 상급 훈장 달성 | 희귀 확정 | `checkAch`에서 `a.tier === '상급'` | — |
| 숙련 단계 훈장 달성 | 전설 확정 | `checkAch`에서 `a.tier === '숙련'` | — |

- **등급 결정**: 확정 드롭이 아니면 가중치 일반 70 / 희귀 25 / 전설 5로 등급을 굴린다.
- **중복 방지**: 굴린 등급에서 아직 없는 것 중 하나를 고른다. 그 등급이 다 찼으면 **아래 등급부터**(전설 → 희귀 → 일반), 아래가 다 찼으면 위 등급으로 넘긴다. 18종이 다 찼으면 XP 15를 준다(`meta.xp`, `run.xpGain`, 새 칸 `run.dropXp`에 더함. 판당 상한 150 밖).
- **기록**: `meta.inv.owned[id] = Date.now()`, `run.drops.push(id)`, 곧바로 `saveMeta()`. 탭을 닫아도 남는다. `G.debug`에서는 사이클 11 규칙대로 저장하지 않는다.
- **알림**: 사이클 11의 `achQueue`에 `{ kind: 'drop', item }`으로 넣어 훈장과 같은 자리·같은 미루기 규칙을 쓴다. `showAch`는 `kind`로 문구만 바꾼다("보관함에 추가 · 희귀" / 이름 / "보관함에서 장착할 수 있습니다").
- **결과 화면**: `showProgress('over')`의 훈장 칩 줄 옆에 `run.drops`를 등급 색 칩으로 붙인다. `runBreakdown`에 `dropXp`를 더하고 0이 아니면 `수집 전환` 줄을 보인다.
- **판 기록**: `submitRun`의 `meta`에 `drops: run.drops`를 더한다.

**수집 속도 다시 셈 (보통 난이도, 보급품은 75%를 줍는다고 가정)**

| 판 | 보스 | 보급품 | 판당 기대 드롭 |
| --- | --- | --- | --- |
| 5웨이브 | 0.4 | 4개 × 0.75 × 0.1 = 0.3 | 약 0.7 |
| 10웨이브 | 0.8 | 9개 × 0.75 × 0.1 = 0.68 | 약 1.5 (+ 상급 '포격 사냥꾼' 1회 확정) |

초안의 "5웨이브 판 약 0.5개"는 보급품을 적게 잡은 값으로 보인다. 중복 방지가 있으므로 18종 수집은 5웨이브 판으로 약 26판, 10웨이브 판으로 약 12판이다. 계급 10 도달 목표(10웨이브 약 10판, 5웨이브 약 27판)와 거의 같은 길이라 "계급 6~10의 빈 구간을 채운다"는 목표에 맞는다. 확률 조정은 밸런스 기획자가 판단한다.

### 3-4. 데이터와 이관 (`fps-meta`, `v: 2`)

```json
{
  "v": 2,
  "inv": {
    "owned": { "d-teal": 1763000000000 },
    "equip": {
      "skin": { "rifle": "desert", "shotgun": null, "sniper": null, "pistol": null, "rocket": null },
      "title": null,
      "killfx": null
    }
  },
  "perksOff": [],
  "tot": { "runs": 0, "kw": {}, "mutClears": {}, "mapClear": {}, "revives": 0, "supply": 0 }
}
```

- `equip.skin[무기]`가 `null`이면 기본색. `title`이 `null`이면 칭호를 표시하지 않는다(계급명을 기본으로 띄우지 않는다. 지금 동료 목록에 계급이 없으므로 화면이 그대로 유지된다).
- **이관 (`load()` 안, `m.v !== 2`일 때 한 번만)**:
  1. `inv`가 없으면 만든다. `equip.skin`의 다섯 무기 모두에 `m.skin === 'base' ? null : m.skin`을 넣는다. `mastery`도 그대로 넣는다(그리는 쪽이 숙련 3단계가 아닌 무기는 기본색으로 칠하므로 사이클 11과 모습이 같다).
  2. `m.skin`은 지우지 않는다(되돌릴 때 대비). 이후 코드는 읽지 않는다.
  3. `meta.ach`에서 상급 훈장 수만큼 희귀, 숙련 단계 훈장 수만큼 전설을 `rollDrop`으로 지급한다. 알림은 띄우지 않고, 다음 메뉴 진입 때 진행 카드에 "보관함에 새 물건 n개"를 한 번 보인다(UX 기획자가 위치를 정한다).
  4. `tot.supply`는 `meta.ach['first-supply']`가 있으면 1, 없으면 0.
  5. `v = 2`, 저장.
- **병합**: `load()`의 마지막 병합에 `inv`도 한 단계 깊게 병합한다(`inv.equip.skin`의 빠진 무기 키를 `null`로 채움).
- **잘못된 장착 정리**: 그리기 직전(`applySkin`)에 `has(id, 무기)`가 거짓이면 기본색으로 그린다. 저장 값은 바꾸지 않는다(계급 계산이 바뀌어도 돌아오면 다시 보임).

### 3-5. 해금 특성과 특화 특성

**공통 구조 (`perks.js`)**

```js
// 새 필드: max(최대 장수), lock(해금 id), weapon(특화 무기)
{ name: '숨 고르기', desc: '자연 회복 대기 30% 단축', max: 2, lock: 'breath', apply: m => { m.regenDelay *= 0.7; } },
```

- 판 시작 때(`startRun`) `meta.js`가 해금된 id 목록을 계산해 `G.unlocks`(Set)에 넣는다. 꺼 둔 것(`meta.perksOff`)은 빼고 넣는다. `perks.js`는 `meta.js`를 불러오지 않고 `G.unlocks`만 본다(순환 참조를 피하고, 판 도중에 풀이 바뀌지 않게 한다). **판 도중에 새로 연 특성은 다음 판부터** 나온다. 해금 알림 문구도 "다음 판부터 카드에 나옵니다"로 쓴다.
- `draw`: 일반 풀은 `!p.rare && !p.weapon && (!p.lock || G.unlocks.has(p.lock)) && !(p.max && G.perks[p.name] >= p.max)`. 희귀 풀은 지금 조건에 `lock` 검사만 더한다.
- 협동: 모든 효과는 각자 로컬이다. 근접 사격의 피해는 `fire`에서 계산된 뒤 `damageEnemy` → `hit` 메시지로 호스트에 간다. 호스트 시뮬레이션은 바뀌지 않는다. 서로 다른 해금 상태의 두 사람이 같은 방에 있어도 주고받는 메시지 형식은 같다.

**해금 특성 4종**

| 특성 | 등급 | 해금 id와 조건 | 구현 위치 |
| --- | --- | --- | --- |
| 숨 고르기 | 일반, 2장까지 | `breath`: `meta.ach['boss-1']` | `BASE_MODS.regenDelay = 1`, `player.js` 145행 `PLAYER.REGEN_DELAY * G.mods.regenDelay` |
| 근접 사격 | 일반, 2장까지 | `close`: `masteryTier('shotgun').tier >= 1` | `BASE_MODS.close = 1`, `weapons.js` 317행 다음 줄 `if (h.distance < 10) dmg *= G.mods.close` |
| 보급 전문가 | 희귀 | `supplier`: `meta.tot.supply >= 5` | `BASE_MODS.supply2 = false`, `main.js` `supplyPick`에서 효과 3종을 섞어 앞의 1개(켜져 있으면 2개)를 적용 |
| 전리품 | 희귀 | `loot`: `meta.ach['up-5']` | `BASE_MODS.loot = 1`, `main.js` 처치 훅 89행 `addCredits(… × G.mods.loot)` |

**특화 특성 4종: 보장 카드 방식**

초안의 "조건을 넘으면 일반 풀에 섞임" 대신 다음 규칙을 권한다.

- 조건: 그 무기 숙련 2단계 이상, 꺼 두지 않음, 이번 판에 아직 그 특화 특성을 받지 않음, 이번 판에 그 무기로 10처치 이상.
- 조건을 처음 넘은 뒤 **다음 특성 선택에서 세 번째 카드 한 장을 특화 특성으로 바꿔 보여 준다**(카드에 무기 아이콘과 "특화" 표시). 고르지 않으면 이번 판에는 다시 보장되지 않고 **일반 풀에도 들어가지 않는다**.
- 다시 뽑기(R)를 해도 그 선택 안에서는 세 번째 카드가 특화 특성으로 남는다(다시 뽑기로 날려 버리는 실수를 막음).
- 한 선택에서 두 무기가 동시에 조건을 넘으면 이번 판 처치가 많은 무기 하나만 보인다. 다른 하나는 다음 선택으로 미룬다.
- 시간 초과 무작위 지급(`closePerks(true)`)으로 특화 특성이 뽑히면 그대로 준다.

이유: (1) 일반 풀 희석이 0이다. (2) "이 무기를 계속 써서 카드를 받았다"는 인과가 한 번에 보인다. (3) 한 판에 무기당 최대 1장이라 쌓기 문제가 없다. 대신 세 장 중 한 장이 특화로 고정되는 선택이 무기당 판마다 한 번 생긴다. 이것이 원하는 특성을 볼 기회를 한 번 줄이는데, 일반 풀에 상시로 섞는 것(매 선택마다 희석)보다 작다.

| 무기 | 특화 특성 | 효과 | 구현 위치 |
| --- | --- | --- | --- |
| 소총 | 점사 제어 | 소총을 들었을 때 연사 시 퍼짐 누적 상승 30% 감소 (0.22 → 0.154) | `weapons.js` 342행 `W.recoil` 증가분 |
| 샷건 | 슬러그 장전 | 샷건 정조준 중 산탄 퍼짐 40% 감소 (`adsSpreadMul` 0.7 → 0.42) | `weapons.js` `currentSpread` 255행 |
| 저격총 | 호흡 정지 | 저격총 정조준(`W.ads > 0.9`)을 1.5초 유지하는 동안 수평 속도가 1 이하이면, 다음 한 발의 피해 +25%. 쏘거나 정조준을 풀거나 움직이면 타이머 0 | 새 값 `W.steady`를 `updateWeapons`에서 갱신, `fire` 316행에서 곱함. 조준선에 준비 표시가 필요(UX) |
| 권총 | 권총 명사수 (초안 '속사 권총' 대체) | 권총을 허리 사격할 때 퍼짐 50% 감소 (`hip`을 반으로) | `weapons.js` `currentSpread` 254행 |

- 로켓은 보급품 전용 무기라 특화 특성이 없다. 숙련표에 "숙련 2단계 보상 없음"을 적는다.
- 모든 특화 효과는 `W.current === 무기` 조건 안에서만 계산한다. 피해(호흡 정지)는 `hit` 메시지로 호스트에 가고, 퍼짐은 로컬 사격 판정이라 협동 영향이 없다.

### 3-6. 칭호의 협동 전달

- `net.js` `connect(name, room, title)`: `join`에 `title`(물건 id 문자열) 추가. `RemotePlayer`에 `title` 칸.
- `server.js` `join` 처리: `const title = typeof msg.title === 'string' && /^[a-z0-9-]{1,24}$/.test(msg.title) ? msg.title : null;`을 `room.clients`에 함께 저장하고, `welcome.players`와 `playerJoined`에 `title`을 넣는다.
- 받는 쪽은 id를 `META.items`에서 찾아 이름을 보인다. **모르는 id나 칭호가 아닌 id는 표시하지 않는다.** 서버는 글자를 저장하지 않고 id만 넘기므로 임의 문구를 띄울 수 없다.
- 보내는 쪽은 `has(title)`가 참일 때만 보낸다. 조작해서 보내도 남의 화면에 이름이 하나 보일 뿐 판에는 영향이 없다.
- 표시 위치: `hud.js` 162행 동료 목록과 `nameSprite`. 배치는 UX 기획자에게 넘긴다.

### 3-7. 범위와 순서 (총괄 순서 2~4에 대한 수정)

1. 카탈로그(`META.items`)와 `has`, `v: 2` 이관, `setGunSkin` 확장, `applySkin` 무기별, 처치 연출
2. 드롭(`rollDrop`, 보스·보급·훈장, 협동 `pkt` 굴림), 알림·결과 화면 칩, 판 기록 `drops`
3. 칭호(`join` 전달)
4. 해금 특성 4종 + `G.unlocks` + `max` + 켜고 끄기
5. 특화 특성 4종(보장 카드)
6. 보관함 패널(UX 안에 따름)

순위표 칭호는 빼고 사이클 13 일일 순위와 함께 다룬다.

## 4. 검증 방법

**시나리오 테스트 (`G.metaTest`, `rollDrop`의 `rng` 고정)**

- 이관: `v: 1`에 `skin: 'olive'`인 저장 → `equip.skin` 다섯 무기 모두 `olive`, `v: 2`. 다시 불러도 이관이 다시 돌지 않는다. `skin: 'mastery'`이고 소총만 숙련 3단계 → 소총만 금색. `meta.ach`에 `warlord`·`wave-15`가 있으면 희귀 1, 전설 1이 들어 있다.
- 중복 방지: `rng`를 0으로 고정해 30번 굴림 → 18종이 한 번씩 들어오고 19번째부터 XP 15. 일반이 다 찬 상태에서 일반을 굴리면 희귀가 나온다. 전설 2종이 찬 상태에서 숙련 단계 훈장 → 희귀.
- 보스 드롭: 5웨이브 클리어 후 같은 `info`로 `metaWaveClear`를 다시 부르면 드롭이 늘지 않는다. `metaWaveStart`를 거치지 않고 5웨이브 클리어만 받은 경우(중간 참가) 드롭을 굴리지 않는다.
- XP 내역: 수집 전환이 있는 판의 결과 화면 합계 = 내역의 합.
- 해금: '첫 보스'를 딴 판에서는 숨 고르기가 카드에 나오지 않고 다음 판부터 나온다. `perksOff`에 넣으면 나오지 않는다. 숨 고르기를 2장 받은 뒤 세 번째로 나오지 않는다.
- 특화: 소총 숙련 2단계 + 이번 판 소총 10처치 → 다음 선택의 세 번째 카드가 점사 제어. R을 눌러도 남는다. 고르지 않으면 이번 판에 다시 나오지 않는다. 숙련 1단계면 나오지 않는다. 샷건을 든 상태에서는 점사 제어의 `W.recoil` 증가가 줄지 않는다.

**협동 테스트 (`tools/test-coop-systems.js` 확장)**

- 2인이 5웨이브를 클리어 → 두 클라이언트가 각자 한 번씩 굴림. 호스트가 나가 같은 웨이브 클리어가 다시 와도 추가 굴림 없음.
- A가 보급품을 주움 → A는 `supplyPick`에서, B는 `pkt` 수신에서 각자 한 번 굴림. 굴림 수 합계 2.
- 칭호: A가 칭호를 단 채 접속 → B의 `net.players.get(A).title`이 그 id. 잘못된 문자열(`<b>`, 30자)을 보내면 서버가 `null`로 넘긴다.
- 해금 상태가 다른 두 사람(A는 근접 사격 2장, B는 없음)이 같은 적을 쏨 → 호스트의 적 체력 감소가 각자 보낸 `hit.dmg`와 같고, 동기화 오류 없음.

**봇 비교**

- 해금 특성 4종 켜짐/꺼짐 × 6판, 도달 웨이브 차이 1웨이브 안. 봇은 항상 첫 카드를 고르므로 특화 보장 카드(세 번째)는 봇 비교에 나타나지 않는다. 특화 특성은 "봇이 세 번째 카드를 고르는" 설정으로 따로 6판 돌린다.

**사람 판 (D 도구로 확인)**

- 판당 드롭 수의 실측이 3-3의 기대값(5웨이브 약 0.7, 10웨이브 약 1.5)과 ±30% 안인지.
- 특화 보장 카드가 나온 선택에서 그 카드를 고른 비율. 30% 미만이면 효과가 약하거나 보장 방식이 거슬린다는 뜻이니 다시 본다.
- 해금 특성을 끈 사람의 비율. 끄는 사람이 많으면 희석이 실제로 불편하다는 근거가 된다.
