# 사이클 11 기획안 — 시스템 기획자

주제: 성장·재도전 동기. 판이 끝나도 남는 진행(해금, 도전 과제, 기록)을 이번 사이클의 중심 축으로 설계한다.

읽은 것: `docs/PLAN.md`(사이클 1~10), `README.md`, `docs/planning/cycle-7/system-designer.md`, `docs/planning/cycle-9/system-designer.md`, `data/runs.jsonl`(5판), `public/js/main.js`, `config.js`, `perks.js`, `shop.js`, `state.js`, `player.js`, `weapons.js`·`enemies.js`(해당 부분), `server.js`(API 부분).
코드는 읽기만 했고 플레이테스트는 돌리지 않았다. 아래 수치는 코드 값과 판 기록 5판으로 계산한 것이다.

| 구분 | 제목 | 비용 | 한 줄 근거 |
| --- | --- | --- | --- |
| 진단 | 판 사이에 남는 것이 최고 기록 숫자 4개뿐이고, 판 안 성장은 1웨이브를 넘겨야 시작된다 | — | `fps-records` 4필드, `resetGame`이 모든 진행을 0으로, 사람 5판 중 4판이 1웨이브 27초 안에 끝남 |
| 구조안 A | 영구 능력치 트리(재화로 체력·피해 % 구매) | 낮음 | 비추천 — 인플레이션이 특성 곱셈과 겹친다 |
| 구조안 B | **계급 + 보급 슬롯 + 훈장(도전 과제)** | 중간 | **추천** — 성장은 판 안 자원으로만 변환되고 슬롯 수로 상한이 걸린다 |
| 구조안 C | 영구 무기 숙련 + 도전 과제만(수평 전용) | 중간 | 부분 채택 — 목표는 생기지만 1웨이브 사망자에게 주는 것이 없다. B의 훈장으로 흡수 |

## 1. 진단

### 1-1. 판 사이에 남는 것 (코드 전수 확인)

| 저장소 | 내용 | 다음 판에 주는 영향 |
| --- | --- | --- |
| `localStorage` `fps-settings` (`state.js` 31행) | 감도·시야각·음량·난이도·맵·이름·그래픽 | 없음 (설정) |
| `localStorage` `fps-hints` (`main.js` 24행) | 본 힌트 목록 | 힌트가 안 뜰 뿐 |
| `localStorage` `fps-records` (`main.js` 294~298, 314~318행) | `bestScore`, `bestWave`, `runs`, `kills` | 메뉴 한 줄과 결과 화면의 "최고 기록" 표시뿐 |
| 서버 `data/scores.json` | 이름·점수·웨이브·난이도·협동 여부 | 메뉴의 순위 5줄 |
| 서버 `data/runs.jsonl` | 판 기록 (기획 검증용) | 플레이어에게 보이지 않음 |

판을 시작하면 `resetGame`(`main.js` 196행)이 `resetShop`(크레딧·아이템·강화·개입권 0), `resetPerks`(특성·`G.mods` 초기값), `resetWeapons`(탄약·수류탄 3개)를 부른다. **판 안의 성장은 하나도 이월되지 않고, 판 밖의 성장은 존재하지 않는다.**

또한 잠긴 콘텐츠가 없다. 무기 4종은 처음부터 다 들고 시작하고(`resetWeapons`), 특성 13종은 처음부터 전부 뽑기 풀에 있으며(`perks.js` `draw`), 맵 2종·난이도 3단계도 처음부터 열려 있다. 해금으로 보여 줄 "다음"이 없다.

### 1-2. 플레이어가 겪는 문제

**문제 1. 대부분의 판이 판 안 성장에 닿기 전에 끝나, 그 판에서 얻은 것이 0이다.**

| 판 | 난이도 | 도달 | 생존 | 처치 | 번 크레딧 | 특성 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 어려움 | 3 | 85초 | 19 | 340 | 빠른 손 ×2 |
| 2 | 어려움 | 1 | 23초 | 2 | 25 | 없음 |
| 3 | 어려움 | 1 | 10초 | 1 | 10 | 없음 |
| 4 | 보통 | 1 | 27초 | 1 | 10 | 없음 |
| 5 | 보통 | 1 | 16초 | 0 | 0 | 없음 |

- 첫 특성은 1웨이브 클리어 뒤(`G.hooks.waveClear` → `offerPerks`), 상점은 웨이브 사이에만 열린다(`canShop`). 5판 중 4판은 둘 다 보지 못했다. 상점은 5판 모두 `shopSeen: false`.
- 이 4판이 남긴 것은 `fps-records.runs`가 1 오른 것뿐이다. "다시 하면 무엇이 나아지는가"에 대한 게임의 답이 "당신의 실력"밖에 없다.
- 사망 원인은 5판 중 4판이 병사 근접이다. 1웨이브는 병사만 `round(5.7 × 난이도 배율)`마리(보통 6, 어려움 7)이고 어려움은 피해 1.35배다. 메타 성장이 이 문제의 근본 해결은 아니며(밸런스·레벨 몫), 메타 성장은 "죽어도 남는 것"을 만드는 역할로 한정한다.

**문제 2. 잘하는 플레이어에게도 판을 반복할 목표가 점수 경신 하나뿐이다.**

- 결과 화면(`gameOver`)은 이번 판 통계와 최고 기록 한 줄을 보여 준다. 다음 판에 노릴 구체적 목표(특정 보스 격파, 특정 무기로 몇 처치, 안 해 본 맵)가 제시되지 않는다.
- `G.stats.kw`(무기별 처치), `supplyPicked`, `bought`, `W.lv`, `G.perks` 같은 판 기록은 이미 모으고 있지만(`submitRun`) 서버로만 가고 플레이어에게 돌아오지 않는다. 목표의 재료가 있는데 쓰이지 않는다.
- 사이클 7에서 낸 일일 도전은 "순위표 사용 여부 확인" 조건으로 보류됐다. 이번 안은 그것을 다시 내지 않는다.

**문제 3. 협동에서 판 밖 보상을 주려면 기준이 필요한데 지금은 없다.**

- 협동은 호스트가 적·웨이브를 시뮬레이션하고(`updateWaves`의 `net.isHost`), 참가자의 난이도는 호스트 스냅샷(`es`의 `d`)으로 덮어쓴다. 피해는 쏘는 쪽이 계산해 `hit`으로 보내고(`damageEnemy`), 받는 피해는 각자 `hurtPlayer`에서 줄인다.
- 즉 "각 클라이언트의 로컬 값"으로 만든 성장은 메시지 추가 없이 동작하지만, "호스트가 시뮬레이션하는 값"을 건드리는 성장은 방 전체를 바꾼다. 메타 성장은 이 경계를 넘지 않게 설계해야 한다.

### 1-3. 메타 성장이 지켜야 할 조건 (진단에서 도출)

1. 1웨이브에서 죽은 판도 눈에 보이는 진행을 남긴다.
2. 판 밖 성장은 판 안 시스템(아이템·강화·개입권·특성)의 기존 상한을 통과해서만 힘이 된다. 별도 배율을 만들지 않는다.
3. 상한이 있다. 오래 한 사람과 처음 한 사람의 차이는 "초반 몇 웨이브분"이어야 하고, 후반 밸런스표(밸런스 기획자의 웨이브별 계산)를 바꾸지 않아야 한다.
4. 효과는 전부 클라이언트 로컬 값이다. 호스트 시뮬레이션(적 체력·속도·스폰·보급품 투하)을 바꾸지 않는다.

## 2. 구조안 비교

### 구조안 A. 영구 능력치 트리

판이 끝나면 재화(훈장)를 받고, 메뉴에서 영구 능력치를 산다. 예) 최대 체력 +5 × 5단계, 모든 피해 +2% × 5단계, 재장전 −3% × 5단계.

| 항목 | 판단 |
| --- | --- |
| 가치 | 높음(초보) — 1웨이브 사망자가 직접 강해진다. 성장 체감이 가장 분명하다 |
| 비용 | 낮음 — `BASE_MODS`(`perks.js` 27행)의 초기값만 바꾸면 된다 |
| 위험 | **높음.** 피해 +10%가 `G.mods.dmg`에 곱해지면 특성 '강화 탄환'(×1.15, 상한 없음)·강화(+10%/단계)와 다시 곱해진다(`enemies.js` 516행). 밸런스 기획자의 웨이브별 화력표가 플레이어마다 달라진다. 순위표 점수가 실력보다 누적 시간을 반영한다. 사이클 8·10에서 정리한 "특성은 플레이어 성장, 상점은 무기 성장" 구분 위에 세 번째 수치 경로가 생긴다 |
| 판정 | 비추천 |

### 구조안 B. 계급 + 보급 슬롯 + 훈장 (추천)

- **계급**: 모든 판이 경험치(XP)를 남긴다. XP가 쌓이면 계급이 오르고, 계급마다 정해진 것이 하나씩 열린다.
- **보급 슬롯**: 열린 것 중 최대 3개를 골라 판을 시작한다. 전부 기존 판 안 자원(구급 주사, 방어막, 다시 뽑기권, +1 강화 등)으로 지급된다.
- **훈장(도전 과제)**: 구체적 목표 19개. 달성하면 XP와 함께 새 특성(뽑기 풀에 추가)이나 칭호가 열린다.

| 항목 | 판단 |
| --- | --- |
| 가치 | 높음 — 짧은 판도 XP를 남기고(조건 1), 보급 슬롯이 초반 생존을 돕고, 훈장이 숙련자의 다음 목표가 된다 |
| 비용 | 중간 — 새 모듈 1개(`meta.js`) + 메뉴의 슬롯 선택 + 결과 화면 줄 |
| 위험 | 중간 — 슬롯 수(3)와 슬롯 가치(판 안 크레딧 환산 최대 390)로 상한을 건다. 아래 3-7 |
| 판정 | **추천** |

### 구조안 C. 영구 무기 숙련 + 도전 과제만 (수평 전용)

무기별 누적 처치로 숙련 단계가 오르고, 단계 보상은 칭호·무기 도색 같은 외형뿐. 힘은 전혀 주지 않는다.

| 항목 | 판단 |
| --- | --- |
| 가치 | 중간 — 숙련자에게는 목표가 생기지만, 1웨이브에서 죽는 플레이어에게 주는 것이 없다(조건 1 실패). 외형 보상의 가치는 아트 품질에 좌우된다 |
| 비용 | 중간 — 도색은 무기 모델 재질 수정, 칭호는 낮음 |
| 위험 | 낮음 |
| 판정 | 부분 채택 — 무기별 누적 처치 목표를 B의 훈장으로 흡수한다. 사이클 7의 판 안 숙련안(→ 사이클 10 강화 고유 효과로 대체)을 다시 내는 것이 아니라, 판을 넘는 누적 기록을 목표로 쓰는 것이다 |

## 3. 추천안 상세 설계 (구조안 B)

### 3-1. 저장 위치와 데이터 형식

`localStorage` 새 키 `fps-meta`. 기존 세 키는 건드리지 않는다.

```json
{
  "v": 1,
  "xp": 412,
  "kit": ["medkit", "reroll", null],
  "kitWeapon": "shotgun",
  "ach": { "first-kill": 1762800000000, "first-clear": 1762800100000 },
  "tot": {
    "kills": 57, "heads": 30, "clears": 6, "supply": 1, "revives": 0,
    "kw": { "rifle": 40, "shotgun": 9, "sniper": 6, "pistol": 2 },
    "mutClears": { "frenzy": 1 },
    "mapClear": { "arena": 2, "depot": 3 }
  },
  "perksOff": [],
  "title": ""
}
```

- 계급은 저장하지 않고 `xp`에서 매번 계산한다(값이 어긋날 여지를 없앤다).
- `tot`은 훈장 판정용 누적 기록이다. `mapClear`는 맵별 최고 클리어 웨이브. `perksOff`는 끈 해금 특성(3-5).
- 판 안의 진행은 메모리의 `G.metaRun = { xp: 0, bankedWave: 0, kills: 0 }`에 두고 아래 3-2의 시점에 `fps-meta`로 옮긴다.
- 기존 플레이어 이관: `fps-meta`가 없고 `fps-records.runs > 0`이면 `xp = min(450, rec.kills + rec.bestWave × 20)`으로 시작한다(최대 계급 6). 훈장은 소급하지 않는다.
- 서버: 판 기록(`/api/runs`)에 `meta: { rank, kit, xpGain, ach: [이번 판에 딴 훈장 id] }`를 추가한다. 현재 한 줄이 약 700바이트라 서버 상한 4,000바이트(`server.js` 60행) 안이다. 순위표(`/api/scores`)에는 `kit`(사용한 슬롯 수 0~3)과 `title`을 추가한다.
- `G.debug`(봇·자동 테스트)에서는 읽기만 하고 쓰지 않는다(`submitRun`과 같은 조건).

### 3-2. XP 획득 공식

```
판 XP = round( D × ( Σ클리어한 웨이브 10n (보스 웨이브는 20n) + 내 처치 수 ) ) + 참전 10 + 이번 판 훈장 XP
D = 쉬움 0.75 / 보통 1 / 어려움 1.25   (게임 오버 시점의 G.diff — 협동 참가자는 호스트 난이도)
```

- 소환병 처치(`info.nr`)는 0. 크레딧과 같은 기준(사이클 9).
- 참전 10은 사격 1회 이상(`G.stats.shots > 0`)일 때 한 번. 켜 놓고 방치한 판(5번 판: 사격 0)은 0이다.
- 적립 시점: 웨이브 클리어(`G.hooks.waveClear`), 게임 오버, 메인 메뉴로 나가기(`toMenu`), 탭 닫기(`pagehide`). 웨이브 클리어 적립은 `n > bankedWave`일 때만 한다(같은 웨이브가 두 번 오면 무시). 판을 버려도 그때까지의 XP는 남는다.

예시 (참전 10 포함, 훈장 제외):

| 판 | 계산 | XP |
| --- | --- | --- |
| 보통, 1웨이브 사망, 1처치 (4번 판) | 1 + 10 | 11 |
| 어려움, 3웨이브 사망, 19처치 (1번 판) | (10 + 20 + 19) × 1.25 + 10 | 71 |
| 보통, 10웨이브 사망, 약 110처치 (봇 수준) | (Σ10n, n=1~9 → 450, 5웨이브 +50) + 110 + 10 | 620 |
| 보통, 15웨이브 사망, 약 230처치 | 1,050 + 50 + 100 + 230 + 10 | 1,440 |

웨이브 XP가 `10n`으로 늘어나 깊이 간 판이 크게 보상받고, 처치 1점이 얕은 판에도 바닥을 깔아 준다.

### 3-3. 계급 문턱과 해금 목록

| 계급 | 누적 XP | 열리는 것 | 판 안 환산 가치 |
| --- | --- | --- | --- |
| 1 | 0 | — | — |
| 2 | 30 | **보급 슬롯 1** + 구급 주사 1개 지참 | 60 크레딧 |
| 3 | 80 | 수류탄 +1 (시작 3 → 4, 상한 4는 그대로) | 탄약 픽업 1회분 |
| 4 | 160 | 다시 뽑기권 1장 지참 | 40 |
| 5 | 280 | **보급 슬롯 2** + 방어막 1개 지참 | 90 |
| 6 | 450 | 주무기 +1 강화로 시작 (메뉴에서 소총·샷건·저격총·권총 중 지정) | 60 |
| 7 | 680 | 시작 크레딧 100 | 100 |
| 8 | 980 | 폭격 요청 1개 지참 | 140 |
| 9 | 1,350 | 희귀 보장권 1장 지참 | 150 |
| 10 | 1,800 | **보급 슬롯 3** + 칭호 '베테랑' | — |

- 지참품 하나가 슬롯 하나다. 같은 것을 두 슬롯에 넣을 수 없다.
- 지급은 `resetGame` 끝에서 한다: `G.inv.medkit = 1`, `player.grenades = 4`, `G.tickets.reroll = 1`, `W.lv[kitWeapon] = 1`, `G.credits = 100`(이때 `G.earned`에는 넣지 않는다 — 판 기록의 번 크레딧과 구분) 등. 전부 기존 필드이고 기존 상한(`ITEMS.max`, `UPGRADE.max`, 개입권 `max`)을 넘지 않는다.
- 진행 속도 추정: 4번 판 같은 판(11 XP)도 입문 훈장(아래, 20~30 XP)과 합쳐 1~2판이면 계급 2가 된다. 1번 판 수준(71 XP + 입문 훈장)이면 한 판에 계급 3. 10웨이브를 가는 플레이어는 3판 안팎에 계급 10에 닿는다.

### 3-5. 훈장으로 열리는 특성 4종 (초안, 수치는 밸런스 기획자 검토)

해금되면 그 판부터 `draw`의 뽑기 풀에 들어간다(`PERKS`를 `meta`의 해금 목록으로 거른다). 모두 쏘는 사람·받는 사람의 로컬 값만 바꾼다.

| 특성 | 등급 | 효과 | 계산 위치 |
| --- | --- | --- | --- |
| 숨 고르기 | 일반 | 자연 회복 대기 5초 → ×0.7 (중첩, 최소 2초) | `player.js` 145행의 `REGEN_DELAY`에 `G.mods.regenDelay` 곱 |
| 근접 사격 | 일반 | 10m 안의 적에게 주는 피해 +20% (중첩 가능) | `damageEnemy`에서 `player.p`와 적 거리 |
| 보급 전문가 | 희귀 | 보급품을 주우면 효과를 2가지 받는다(중복 없이 무작위) | `G.hooks.supplyPick` |
| 전리품 | 희귀 | 처치 크레딧 +30% | `G.hooks.kill`의 `addCredits` |

- 일반 특성 풀이 8 → 10장으로 늘어 기존 특성 하나가 3장 안에 나올 확률이 약 37.5%에서 약 30%로 준다. 원하지 않는 희석을 막기 위해 메뉴에서 해금 특성을 끌 수 있게 한다(켜짐이 기본, `perksOff`).

### 3-6. 판 안 성장과의 관계

| 층 | 언제 | 무엇을 바꾸나 | 상한 |
| --- | --- | --- | --- |
| 메타(계급·훈장) | 판 사이 | **출발점**(보급 슬롯 3개)과 **선택지**(특성 풀 +4, 칭호) | 슬롯 3, 계급 10 이후 힘 없음 |
| 특성 | 웨이브 클리어마다 | 플레이어 능력 | 기존 그대로 |
| 상점·강화 | 웨이브 사이 | 무기·소모품 | 기존 그대로(+7, 아이템 `max`) |

- 메타는 새 수치 경로를 만들지 않는다. 보급 슬롯은 판 안의 아이템·개입권·강화·크레딧으로 바뀌어 들어오므로, 판 안 상한이 그대로 메타 성장의 상한이다.
- 슬롯 지참품은 "상점을 열어 볼 이유"도 겸한다. 다시 뽑기권·희귀 보장권·+1 강화를 들고 시작하면 첫 클리어에서 특성 카드와 상점 화면이 그것을 쓰는 자리가 된다.

### 3-7. 파워 인플레이션 억제

1. **총량 상한**: 슬롯 3개의 최대 가치는 희귀 보장권 150 + 폭격 140 + 시작 크레딧 100 = 390 크레딧 상당이다. 솔로·보통 누적 수입(사이클 9 계산: 5웨이브 약 810, 10웨이브 약 2,430, 15웨이브 약 4,540) 대비 5웨이브까지 약 48%, 10웨이브까지 약 16%, 15웨이브까지 약 9%다. **초반에 크고 후반으로 갈수록 묻힌다.** 1웨이브 사망이 문제인 초보에게는 도움이 되고, 밸런스 기획자의 10웨이브 이후 표는 거의 바뀌지 않는다.
2. **수치 % 없음**: 계급 보상에 피해·체력 배율이 하나도 없다. 해금 특성은 기존 특성과 같은 크기 대(+15~30%)이며 판 안 뽑기를 거쳐야 얻는다.
3. **힘의 끝**: 계급 10 이후는 칭호만. 오래 한 사람과 계급 10인 사람의 힘은 같다.
4. **비우는 쪽의 보상**: 도전 훈장 '맨몸'(슬롯 없이 10웨이브)이 숙련자에게 지참품을 빼고 플레이할 이유를 준다.
5. **기록으로 감시**: 판 기록에 `meta.kit`, 순위표에 `kit`을 남겨 슬롯 수별 도달 웨이브를 비교한다(6장 판정 기준).

### 3-8. 협동에서의 동기화와 공정성

| 항목 | 처리 | 근거 |
| --- | --- | --- |
| 지참품 효과 | 각 클라이언트가 `resetGame` 끝에서 자기 것만 지급. 메시지 추가 없음 | `G.inv`·`W.lv`·`G.tickets`·`G.credits`·`player.grenades`는 전부 로컬. 피해는 `hit`의 `dmg`로 이미 실려 감 |
| 해금 특성 | 전부 로컬 계산(3-5 표). 호스트 쪽 `takeDamage`나 적 AI를 바꾸지 않음 | 사이클 7 무기 숙련안에서 확인한 경계(경직 판정은 호스트) |
| 설계 규칙 | **메타 효과는 호스트 시뮬레이션(적 체력·속도·스폰·투하·경직)을 바꾸지 않는다.** 이 규칙을 넘는 해금은 내지 않는다 | 방 전체에 영향 |
| 재시작 | 호스트가 다시 시작하면 `restart` 메시지 → 모두 `resetGame` → 각자 지참품 재지급 | `main.js` 478행 |
| 웨이브 XP | **팀 공통**: 내가 방에 있을 때 시작된 웨이브가 클리어되면 쓰러져 있어도 받는다. 처치 XP만 개인 | 막타 경쟁 방지(사이클 9 지원 수당과 같은 취지). 협동은 쓰러지면 클리어 때 부활하는 구조라 쓰러진 사람도 팀 결과의 일부 |
| 보스 훈장 | 웨이브 클리어 기준이라 막타와 무관 | `boss-1`, `warlord` |
| 난이도 배율 | 게임 오버·클리어 시점의 `G.diff` = 호스트 난이도 | `es`의 `d` |
| 호스트 이전 | 새 호스트가 웨이브를 다시 굴려도 클리어 적립은 `n > bankedWave`일 때만 | `net.on('host')`가 `waves`를 재설정(`enemies.js` 991행) |
| 도중 참가 | 참가 이후 시작된 웨이브부터 XP. 지참품은 참가 시 지급 | `btnMulti` → `resetGame` |
| 나갔다 들어오기 | 지참품을 다시 받지만 크레딧·강화·특성을 전부 잃으므로 이득이 없다(사이클 9 늦참 검토와 같은 구조) | `resetShop` |
| 계급 격차 | 계급 1과 10의 차이는 최대 390 크레딧 상당. 지원 수당 25%로 수입 격차도 좁혀져 있음 | 3-7 |
| 조작 | `localStorage`를 고치면 계급을 올릴 수 있다. 점수와 같은 수준으로 허용(지인 서버, 사이클 4 판단) | — |

협동에서 처치 XP는 나눠 갖지만 웨이브 XP는 모두 받으므로, 같은 웨이브까지 가면 솔로보다 XP가 처치분만큼 약간 적다. 협동을 피할 이유가 되지 않을 정도의 차이로 봤다. 대신 협동 전용 훈장(`revive-5`)이 있다.

### 3-9. 화면에 필요한 것 (배치는 UX 기획자)

- 결과 화면: 이번 판 XP 내역(웨이브 / 처치 / 참전 / 훈장), 계급 막대(다음 계급까지 남은 XP), 이번 판에 딴 훈장, 새로 열린 것.
- 메뉴: 계급과 칭호, 보급 슬롯 선택(열린 슬롯 수만큼), +1 강화 무기 지정, 훈장 목록(딴 것 / 남은 조건), 해금 특성 켜기·끄기.
- 판 중: 훈장을 따면 피드 한 줄(`G.hooks.feed`).

## 6. 검증 방법

### 시나리오 테스트 (`node tools/playtest.js run`)

1. XP 공식: `G.stats`와 클리어 웨이브를 주입해 3-2의 예시 4개가 같은 값이 나오는지. 사격 0이면 참전 0, 소환병 처치 0.
2. 적립: 3웨이브 클리어 직후 `toMenu` → `fps-meta.xp`에 1~3웨이브 XP가 있는지. 같은 웨이브 클리어를 두 번 보내도 한 번만 오르는지.
3. 지참품: 계급 10·슬롯 3(구급 주사, 다시 뽑기권, 소총 +1)으로 솔로 시작 → `G.inv.medkit = 1`, 첫 특성 선택에서 다시 뽑기 2회, `W.lv.rifle = 1`, `G.earned = 0`. 게임 오버 후 다시 시작해도 같은지.

### 협동 테스트 (`tools/test-coop-systems.js` 확장)

- A(계급 10, 슬롯 3)와 B(계급 1)가 같은 방: B의 아이템·강화가 0, A의 지참품이 A에게만.
