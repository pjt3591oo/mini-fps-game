# 사이클 7 기획안 — UX 기획자

읽은 것: `docs/PLAN.md`(사이클 1~6), `docs/screenshots/` 3장, `public/index.html`, `public/js/hud.js`, `main.js`, `perks.js`, `enemies.js`의 웨이브 진행 부분, `config.js`의 이름·색 정의.
코드와 설정은 수정하지 않았고 플레이테스트 도구도 실행하지 않았다. 아래 근거는 모두 코드와 스크린샷을 읽어서 얻은 것이며, 실제 화면 재현이 필요한 항목은 "확인 방법"에 따로 적었다.

우선순위는 **안 1 > 안 2 > 안 3**이다. 세 안 모두 새 정보를 더하기보다 "이미 있는 안내가 제때, 맞게 전달되는가"를 다룬다.

## 안 1. 특성 선택 10초: 보이지 않는 제한 시간과 잘못 눌리는 키

### 문제와 근거

마지막 적을 잡은 직후의 플레이어는 조준선을 보고 있고, 손은 무기 교체 키(1~3)나 재장전 키(R) 위에 있다. 바로 그 프레임에 같은 키들의 뜻이 바뀐다.

| 문제 | 근거 |
| --- | --- |
| 제한 시간이 화면에 없다. 10초가 지나면 무작위 특성이 지급된다 | `enemies.js` `updateWaves()`의 `waves.timer = 10` → `main.js` `G.hooks.waveStart`의 `closePerks(true)` → `perks.js` `closePerks()`가 무작위 선택. `#perkhint` 문구(`perks.js` `draw()`)에는 키 안내만 있다 |
| 카드가 뜨는 순간부터 1·2·3이 즉시 선택 키가 된다. 입력 유예가 없다 | `main.js` `keydown`: `perkOpen()`이면 `choosePerk(n - 1)`. `offerPerks()`는 `G.hooks.waveClear`에서 마지막 처치와 같은 프레임에 호출된다 |
| R도 같은 순간 '재장전'에서 '다시 뽑기'로 바뀐다. 습관적 재장전 한 번에 1회뿐인 다시 뽑기가 사라진다 | `main.js` `keydown`: `if (perkOpen()) rerollPerks(); else reload();` |
| 카드가 열린 채 Enter를 누르면 1.5초 뒤 무작위 특성이 지급된다. Enter는 보통 '확인' 키다 | `enemies.js` `skipIntermission()`은 `perkOpen()`을 보지 않고 `waves.timer = 1.5`로 줄인다 |
| Enter는 어느 화면에도 적혀 있지 않다 | `index.html` `.keys`에 Enter 행이 없다. `README.md`에만 있다 |
| 협동에서는 고른 뒤에도 남은 시간을 그냥 기다린다. 참가자의 Enter는 아무 일도 하지 않는다 | `updateWaves()`의 조기 시작 조건에 `!net.connected`, 함수 첫 줄 `if (!net.isHost) return` |
| 힌트가 카드 아랫변에 맞닿아 겹치고, 카드를 읽는 동안 소모된다 | `perks.png`: `#hint`("Q로 대시합니다…")가 `#perks` 카드 하단에 붙어 있다. `main.js` `updateHints()`는 `perkOpen()` 중에도 큐를 꺼내며, 한 번 꺼낸 힌트는 다시 나오지 않는다 |
| 같은 순간 화면 중앙 세로축에 5개가 쌓인다 | `#combo`(top 60px), `#banner` "WAVE n 클리어"(top 25%, 2.2초), `#perkhint`, `#perks`, `#hint` |

### 제안

1. **남은 시간 표시.** `#perkhint`를 두 줄로 바꾼다.
   - 1행: `특성을 고르세요 — 1 · 2 · 3    R 다시 뽑기 (1회)` (다시 뽑은 뒤에는 R 부분 삭제, 지금과 동일)
   - 2행: 폭 220px 막대(`#prompt > div` 스타일 재사용) + `8초 뒤 무작위로 지급됩니다`. 숫자가 매초 줄어든다. 3초 이하에서는 막대 색과 함께 글자 굵기도 바꿔 색에만 기대지 않는다.
2. **입력 유예 0.6초.** 카드가 뜬 뒤 0.6초 동안 1·2·3과 R은 특성 쪽으로 가지 않는다(그동안은 평소대로 무기 교체·재장전). 유예 중 카드는 불투명도 50%, `.perk kbd` 테두리는 회색이고 유예가 끝나면 호박색으로 켜진다. 기존 `perkIn` 애니메이션(0.3초 + 지연 0.12초)과 길이가 거의 같아 체감 지연은 없다.
3. **Enter 정리.**
   - 카드가 열려 있는 동안 Enter는 건너뛰기로 동작하지 않고, 1행 문구를 1초간 `먼저 특성을 고르세요`로 바꾼다.
   - 고른 뒤에는 `#perkhint` 자리에 `다음 웨이브까지 4초 · Enter 바로 시작`(솔로·호스트), 참가자에게는 `다음 웨이브 준비 중 (호스트가 시작합니다)`.
   - `index.html` `.keys`에 `Enter — 다음 웨이브 바로 시작` 행을 추가하고, 같은 표의 `1~5`는 `1~4`로 바꾼다(5번 로켓은 획득 시 `#wlist`에 슬롯이 생기므로 표에서 뺀다. 더하는 행 하나, 빼는 표기 하나).
4. **카드가 열린 동안 힌트를 멈춘다.** `updateHints()`가 `perkOpen()`이면 타이머를 깎지 않고 `#hint`를 숨긴다. 클리어 배너는 부제(`보너스 +N · 체력 +25`)를 킬 피드(`addFeed`)로 옮기고 표시 시간을 1.2초로 줄인다.

제한 시간 10초 자체와 다시 뽑기 횟수는 건드리지 않는다. 2·3번은 입력 처리 변경이라 시스템 기획자의 확인이 필요하다.

### 기대 효과
첫 판 플레이어가 "읽는 중에 카드가 사라졌다", "누르지도 않았는데 골라졌다"를 겪지 않는다. Enter의 존재를 필요한 순간에 알게 된다. 웨이브 사이 화면에서 동시에 읽을 글이 5곳에서 2곳(카드, 안내 줄)으로 준다.

### 구현 비용: 낮음~중간
`perks.js`(`draw`, `offerPerks`, 유예·남은 시간 표시), `main.js`(`keydown`, `updateHints`, `G.hooks.waveClear`), `enemies.js`(`skipIntermission`, `waves.timer`는 이미 export된 `waves`로 읽을 수 있음), `index.html`(`#perkhint`, `.perk`, `.keys`).

### 위험과 완화책
- 유예가 답답하게 느껴질 수 있다 → 0.6초를 상한으로 두고 카드 등장 애니메이션과 겹친다.
- 참가자 쪽에는 호스트의 `waves.timer`가 없다 → 참가자는 `clear` 수신 시점부터 자체로 10초를 세고, 어긋나도 문제없도록 숫자 대신 막대만 보여 준다.
- 봇(`updateBot`의 `choosePerk(0)`)이 유예에 막히면 회귀 테스트가 달라진다 → 유예는 키 입력 경로에만 적용하고 `choosePerk` 자체에는 넣지 않는다.

### 성공 확인 방법
- 시나리오(`?debug`): `offerPerks()` 직후 0.3초 시점에 Digit2 입력 → `G.perks`가 비어 있고 무기가 샷건으로 바뀜. 카드가 열린 채 Enter → `waves.timer`가 줄지 않음.
- 화면: 힌트가 큐에 있는 상태로 720p 특성 화면을 찍어 `#hint`가 보이지 않는지 확인.
- 사람 플레이: `closePerks(true)`가 실제로 무작위 지급을 한 횟수를 판당 기록해 전후 비교.

## 안 2. 게임 오버·일시정지 화면: 잘못 눌리는 버튼과 마우스로만 되는 재시작

### 문제와 근거

솔로에서 쓰러진 플레이어는 1.2초 동안 여전히 사격 버튼을 누르고 있다. 그 직후 커서가 풀리며 버튼 두 개가 나타난다.

| 문제 | 근거 |
| --- | --- |
| 게임 오버 버튼이 뜨자마자 눌린다. 결과를 읽기 전에 재시작되거나 메뉴로 나간다 | `main.js` `step()`: `deathT > 1.2`이면 `gameOver()` → `setOverlay('over')`와 `controls.unlock()`이 동시에 실행. `#btnResume`("다시 시작")와 `#btnQuit`("메인 메뉴")에 입력 유예가 없다 |
| "메인 메뉴"를 누르면 결과가 사라진다 | `toMenu()` → `setOverlay('menu', menuText())`가 `#ovsub`의 결과 문구를 덮어쓴다. 판별 통계(명중률 등)는 다시 볼 수 없다 |
| 일시정지의 "메인 메뉴"는 확인 없이 판을 버린다. 기록도 남지 않는다 | `$('btnQuit').onclick = toMenu`. `toMenu()`는 `submitScore()`와 기록 저장(`gameOver()` 안에만 있음)을 거치지 않는다. 버튼은 "계속하기"와 같은 크기로 바로 옆에 있다(`#resume .field`, 둘 다 `flex:1`) |
| 재시작·계속하기에 키보드 경로가 없다 | `main.js` `keydown`: `G.mode !== 'playing'`이면 바로 반환한다. 손을 마우스로 옮겨 버튼을 찾아 눌러야 한다 |
| Esc로 멈춘 직후 "계속하기"가 반응하지 않을 수 있고, 그 사실이 화면에 나오지 않는다 | `enterPlay()`는 `controls.lock()`만 호출한다. `public/js` 전체에 `pointerlockerror` 처리가 없다. 브라우저는 Esc로 잠금이 풀린 직후의 재잠금 요청을 거절한다(실제 브라우저 확인 필요) |
| 일시정지 화면이 지금 판의 상태를 알려 주지 않는다 | `onUnlock()`의 문구는 `일시정지` 한 단어. 웨이브·난이도·맵은 `#menu`가 숨겨지면서 함께 사라진다 |

### 제안

1. **게임 오버 버튼 입력 유예 0.8초.** 그동안 두 버튼은 불투명도 40%에 클릭 불가. 유예가 끝나면 "다시 시작"만 호박색(primary)으로 켜진다.
2. **키보드 경로.** 버튼 문구에 키를 적는다.
   - 게임 오버: `다시 시작 [Enter]` / `메인 메뉴`
   - 일시정지: `계속하기 [Enter]` / `메인 메뉴`
   - Enter는 `#btnResume` 클릭과 같은 동작. 게임 오버에서는 1번의 유예가 끝난 뒤에만 받는다.
3. **일시정지의 "메인 메뉴"는 두 번 누르기.** 첫 클릭에 문구가 3초간 `한 번 더 누르면 종료 — 이번 판 기록은 남지 않습니다`로 바뀌고, 그 안에 다시 누르면 나간다. 게임 오버 화면에서는 기록이 이미 저장됐으므로 한 번에 나간다.
4. **잠금 실패 안내.** `pointerlockerror`가 오면 `#ovsub` 아래에 `잠시 뒤 다시 눌러 주세요`를 2초간 보여 준다.
5. **일시정지 문구에 판 상태 한 줄.** `일시정지` 아래 작은 글씨로 `WAVE 7 · 보통 · 요새 광장 · 12,400점`.

기록 저장 규칙(중도 종료 시 저장 여부)은 바꾸지 않고 사실만 알린다.

### 기대 효과
결과 화면이 실제로 읽힌다(사이클 2에서 넣은 통계가 제 역할을 한다). 재도전이 Enter 한 번으로 끝나 "한 판 더"의 마찰이 준다. 실수로 판을 날리는 일이 없어진다.

### 구현 비용: 낮음
`main.js`(`setOverlay`, `gameOver`, `onUnlock`, `keydown`, `btnQuit`·`btnResume` 처리, `pointerlockerror` 리스너), `index.html`(`#resume` 버튼 문구, 비활성 스타일).

### 위험과 완화책
- Enter가 메뉴 입력란(`#inName`, `#inRoom`)과 충돌 → `keydown`의 기존 `e.target.tagName === 'INPUT'` 반환을 그대로 쓰고, `menu` 상태에서는 Enter를 받지 않는다.
- 협동에서 한 명의 Enter가 전원을 재시작시킨다(`net.send('restart')`) → 지금 버튼도 같은 동작이므로 범위는 같다. 유예 0.8초가 연타로 인한 우발 재시작을 막는다.
- 디버그 모드(`G.debug`)는 잠금을 쓰지 않는다 → 유예와 Enter는 `G.mode` 기준으로만 판단해 헤드리스 테스트에서도 같게 동작한다.

### 성공 확인 방법
- 시나리오: 사망 후 오버레이가 뜬 0.3초 시점에 `#btnResume` 클릭 → `G.mode`가 `over` 그대로. 1초 뒤 Enter → `playing`.
- 시나리오: 일시정지에서 `#btnQuit` 1회 클릭 → `G.mode`가 `paused` 그대로이고 문구가 바뀜.
- 실제 브라우저(사람): Esc 직후 0.5초 안에 "계속하기"를 눌러 안내 문구가 뜨는지 확인. 이 항목은 헤드리스로 검증할 수 없다.

## 안 3. 틀린 안내, 사라지는 힌트, 색 이름에만 기대는 안내

세 항목은 따로 채택할 수 있다. 순서는 3-a > 3-b > 3-c.

### 문제와 근거

**3-a. 10웨이브 보스 배너가 다른 보스의 대처법을 말한다.**
`main.js` `G.hooks.waveStart`는 `info.boss`이면 항상 `바닥의 붉은 띠가 돌진 경로입니다. 옆으로 피하세요!`를 띄운다. 10웨이브마다 나오는 포격대장(`config.js` `warlord`)은 띠가 아니라 원으로 예고한다(`ENEMY_HINTS.warlord`). 또 보스 웨이브에는 변이가 없어 `G.mut ? 3200 : 1800`에서 1.8초가 선택된다. 58px 제목과 한 문장을 읽기에 가장 짧은 시간이 가장 중요한 웨이브에 걸린다. PLAN의 미검증 항목 "포격을 사람이 피할 수 있는가"를 판단하기 전에 안내부터 맞아야 한다.

**3-b. 힌트가 한 번도 보이지 않고 영구히 소모될 수 있다.**
- `main.js` `hint()`는 큐에 넣는 순간 `seenHints[id] = 1`을 저장한다. `resetGame()`은 `hintQueue.length = 0`으로 큐를 비운다. 큐에 있던 힌트는 죽거나 메뉴로 나가면 다시는 나오지 않는다.
- `updateHints()`는 7초에 하나씩 꺼낸다. 새 적 여러 종이 한 웨이브에 나오면 자폭병 힌트가 자폭병이 터진 뒤에 뜬다. 위험 안내(`enemy-*`)와 요령 안내(`barrel` 등)가 같은 줄에 선다.
- `G.hooks.supply`는 `showHint()`를 직접 불러 표시 중인 힌트를 덮어쓴다. 덮인 힌트도 이미 본 것으로 저장돼 있다.

**3-c. 안내 문구와 미니맵이 색으로만 대상을 가리킨다.**
- 문구: `보라색 사수`, `노란 자폭병`, `빨간 드럼통`, `초록 상자는 체력 팩`, `노란 탄약 상자`, `하늘색 빛기둥`·`미니맵의 하늘색 표시`(`main.js` `ENEMY_HINTS`, `hint('barrel')`, `hint('noammo')`, `hint('lowhp')`, `G.hooks.supply`).
- 미니맵(`hud.js` `drawMinimap()`): 체력 팩 `#3cdc64`와 탄약 `#ffc83c`가 같은 3px 사각형이다. 드럼통 `#ff7a20` 2px 사각형과 적 `#ff5a4a` 반지름 2 원은 170px 미니맵에서 모양으로 구분되지 않는다. 쓰러진 동료(`#888`)와 살아 있는 동료(`#4aa8ff`)는 같은 원이다.
- 색 외 단서가 이미 있는 것(변경 불필요): `#hpfill`(숫자 병기), `#ammotext.low`(`#reloadtext` 문구 병기), `#hitmark.kill`(굵기), `.dmgnum`(크기), `.perk .tier`(글자), `#players .dead`(취소선).

### 제안

**3-a.** 배너 부제를 보스 종류에 따라 나누고 보스 웨이브는 3.2초로 한다.
- 돌진형: 지금 문구 그대로.
- 포격대장: `바닥의 붉은 원이 포격 지점입니다. 원이 차기 전에 밖으로 나가세요!`
- 종류 구분은 `info`에 보스 종류를 싣는 방식을 권한다(구현자 판단).

**3-b.**
- '봤음' 저장 시점을 큐 투입에서 **실제 표시**(`updateHints()`가 꺼낼 때)로 옮긴다.
- `enemy-*` 힌트는 큐 맨 앞에 넣는다.
- 보급품 안내는 `showHint()` 직접 호출 대신 큐 맨 앞 투입으로 바꿔 표시 중인 힌트를 끊지 않는다.

**3-c.**
- 미니맵 모양: 체력 팩 = 십자(+), 탄약 = 사각형(유지), 보급품 = 마름모(크기 유지), 드럼통 = 속 빈 사각형, 쓰러진 동료 = 속 빈 원. 색은 그대로 둔다.
- 문구: 색 이름 뒤에 색이 아닌 단서를 하나씩 붙인다. 예: `사수는 쏘기 직전에 몸이 빛납니다`(색 이름 삭제), `자폭병은 빠르게 달려와 터집니다`, `체력 팩(미니맵의 + 표시)`, `빛기둥을 찾아가세요 (미니맵의 마름모 표시)`. 글자 수는 늘리지 않는다.

### 기대 효과
10웨이브 첫 도달자가 틀린 대처법을 안내받지 않는다. 첫 판에서 죽어 넘긴 힌트를 둘째 판에서 받는다. 색각 이상 사용자와 '그래픽: 낮음'(빛 번짐 없음) 사용자도 미니맵에서 회복 수단을 찾을 수 있다.

### 구현 비용: 낮음
`main.js`(`G.hooks.waveStart`, `hint`, `updateHints`, `G.hooks.supply`, 문구), `hud.js`(`drawMinimap`), 3-a를 `info`로 풀 경우 `enemies.js`(`startWave`의 `info`).

### 위험과 완화책
- 3-b로 힌트 노출이 늘어 화면이 시끄러워질 수 있다 → 항목당 1회 원칙은 유지되고, 안 1의 "카드 중 힌트 정지"와 함께 쓰면 겹침은 오히려 준다.
- 3px 크기에서 십자와 사각형이 뭉개질 수 있다 → 십자는 5px, 속 빈 사각형은 4px로 그리고 720p 스크린샷으로 확인한다.
- 협동 참가자는 `info`를 네트워크로 받는다 → 필드가 없으면 지금 문구로 되돌아가게 해 구버전 호스트와도 깨지지 않는다.

### 성공 확인 방법
- 시나리오: 10웨이브 시작 시 `#banner span` 문구가 "원"을 말하는지, 표시가 3초 이상인지.
- 시나리오: 1웨이브 시작 3초 뒤 `toMenu()` → 새 판 → `dash` 힌트가 다시 뜨는지.
- 화면: 체력 팩·탄약·드럼통·적을 한 화면에 두고 찍은 미니맵을 흑백으로 바꿔 네 가지가 구분되는지.

## 검토했지만 내지 않은 것

- 상단 중앙 묶음(`#top` 14px, `#combo` 60px, `#bossbar` 98px, `#buff` 134px)은 720p에서 서로 겹치지 않는다. `#banner`(top 25%)가 `#buff`와 겹치는 것은 창 높이가 약 630px보다 낮을 때뿐이라 우선순위에서 뺐다.
- 보급품 로켓을 주우면 무기가 자동으로 로켓으로 바뀐다(`weapons.js` `grantRocket()`의 `switchWeapon('rocket')`). 사격 중이면 근거리 자폭 위험이 있다. 규칙 변경에 해당해 시스템 기획자에게 넘긴다.
- V(위치 표시)는 솔로에서 쓸모가 없는데 메뉴 조작표에 같은 무게로 실려 있다. 영향이 작아 제외했다.
